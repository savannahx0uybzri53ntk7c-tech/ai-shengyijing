# Contributing

Start with one concrete workflow problem. Include the Skill, synthetic input, actual output,
expected improvement and client/model context when relevant. Never attach private materials or credentials.

Preserve existing capability, input scope and user-approved text. Run the same input for behavior changes;
label instruction review, model execution, independent evaluation and human acceptance separately.
Prose quality is not determined by file counts, prompt length or the author's own rating.

For diagram code:

```sh
python3 skills/html-story/scripts/diagram_compiler.py skills/html-story/examples/flow.json --check-only
```

Use a new output path for compilation. Check generated HTML on phone and desktop when appearance changes;
JSON validation alone does not establish visual quality. Keep changes focused and explain untested modes.

AI-assisted contributions are welcome. Contributors remain responsible for explaining sources, permissions,
scope and the evidence behind the change. Maintainer review is required before merging or releasing.
